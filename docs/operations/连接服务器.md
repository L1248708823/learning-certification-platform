# 连接服务器

状态：持续维护；当前服务器可以通过公网 SSH 地址连接，后续更换服务器时只需更新本地地址变量。

这份文档只负责“我的电脑如何连接服务器”。Docker、MySQL、Redis、MinIO 的部署细节请看
同目录的 [server-docker-teaching-checklist.md](server-docker-teaching-checklist.md)。

## 1. 先分清三类地址

| 地址 | 含义 | 本地电脑是否直接使用 |
| --- | --- | --- |
| `10.1.8.2` | 服务器内网网卡地址 | 通常不能；除非电脑处于同一内网或 VPN |
| `$ServerHost` | 当前服务器公网 SSH 地址 | 当前变量值为 `106.55.229.119`；服务器更换后会变化 |
| `127.0.0.1` | “当前执行命令的机器”自己 | 隧道目标使用它，不能直接当服务器公网地址 |

本次用 `10.1.8.2` 连接时出现超时，是因为 Windows 电脑无法路由到服务器内网。
使用 `$ServerHost` 后已经到达 SSH 主机指纹确认页面，说明公网 SSH 入口可达。

## 2. 地址集中为 PowerShell 变量

不要把服务器地址散落在多条命令里。每次打开新的 PowerShell 窗口，先执行这一段：

```powershell
$ServerHost = "106.55.229.119"
$ServerUser = "ubuntu"
$SshTarget = "$ServerUser@$ServerHost"
```

服务器到期、更换云主机或绑定域名后，只修改 `$ServerHost` 这一行。建议把这三行保存到
自己电脑的本地脚本或 PowerShell 配置中，但不要把个人密钥、密码写入 Git 仓库。

如果以后使用域名，只需要改成：

```powershell
$ServerHost = "server.example.com"
```

## 3. 第一次测试 SSH

先测试 TCP 22 端口：

```powershell
Test-NetConnection $ServerHost -Port 22
```

看到以下结果才继续：

```text
TcpTestSucceeded : True
```

然后测试普通 SSH 登录：

```powershell
ssh -o ConnectTimeout=10 $SshTarget
```

`ConnectTimeout=10` 的作用是避免地址错误时长时间卡住。

### 3.1 首次主机指纹确认

第一次连接可能看到：

```text
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

这是 SSH 在确认服务器身份，不是密码提示。本次服务器 ED25519 指纹为：

```text
SHA256:uWdpemSzYPtGANjVGboMrnHLJ2nFZXBhEVvprMuZKE8
```

核对可信指纹后输入小写 `yes`。确认记录会保存到：

```text
C:\Users\你的用户名\.ssh\known_hosts
```

主机指纹不是登录密码。以后服务器重装或更换后，如果指纹变化，先核对服务器是否确实已经
更换，再处理 `known_hosts`，不要直接关闭安全检查。

### 3.2 SSH 密码和项目密码不是一回事

如果出现：

```text
<ssh-user>@<server-host>'s password:
```

这里要求的是服务器 Linux 用户 `ubuntu` 的登录密码，或者应该改用 SSH 私钥；不是项目的
MySQL、Redis、MinIO 密码。项目密码只用于应用连接，不能拿来登录服务器。

更推荐使用 SSH 私钥：

```powershell
ssh -i "$env:USERPROFILE\.ssh\id_ed25519" -o ConnectTimeout=10 $SshTarget
```

如果你的私钥文件名不同，替换 `id_ed25519`。私钥只保存在自己的电脑或密码管理器中，不能
提交到仓库、发到聊天或复制到文档。

## 4. 建立本地开发隧道

确认普通 SSH 登录成功后，在一个单独的 PowerShell 窗口执行：

```powershell
ssh -N -o ExitOnForwardFailure=yes -o ConnectTimeout=10 -o ServerAliveInterval=60 -o ServerAliveCountMax=3 -L 13306:127.0.0.1:13306 -L 16379:127.0.0.1:16379 -L 19000:127.0.0.1:19000 -L 19001:127.0.0.1:19001 $SshTarget
```

参数含义：

- `-N`：只建立转发，不打开远程 Shell；窗口没有输出是正常现象。
- `-L 本地端口:服务器目标地址:服务器目标端口`：把本地端口转发到服务器。
- 目标里的 `127.0.0.1` 是服务器本机，因为它在 SSH 服务器一侧解析。
- `ExitOnForwardFailure=yes`：本地端口占用时立即报错，不让你误以为隧道成功。
- 关闭这个 PowerShell 窗口，隧道就会断开。

## 5. 隧道建立后的本地连接地址

| 服务 | 本地连接地址 | 说明 |
| --- | --- | --- |
| MySQL | `127.0.0.1:13306` | 用户 `lp_dev`，数据库 `iam` |
| Redis | `127.0.0.1:16379` | 使用服务器生成的 Redis 密码 |
| MinIO API | `http://127.0.0.1:19000` | Java SDK 使用 |
| MinIO Console | `http://127.0.0.1:19001` | 浏览器访问 |

第二个 PowerShell 窗口可以验证本地端口：

```powershell
Test-NetConnection 127.0.0.1 -Port 13306
Test-NetConnection 127.0.0.1 -Port 16379
Test-NetConnection 127.0.0.1 -Port 19000
Test-NetConnection 127.0.0.1 -Port 19001
```

四个端口均显示 `TcpTestSucceeded : True`，才算隧道转发成功。之后再用 DBeaver、IDEA、
Redis 客户端或浏览器做应用层连接测试。

## 6. 更换服务器流程

服务器地址变量只能解决“找到新服务器”，不能自动迁移数据。服务器到期前应按以下顺序处理：

1. 在旧服务器完成 MySQL、Redis、MinIO 的正式备份，并验证备份可以恢复。
2. 创建新服务器，确认 SSH 用户、SSH 密钥和安全组规则。
3. 先修改本地 `$ServerHost`，不要急着删除旧服务器。
4. 执行 `Test-NetConnection` 和普通 SSH 登录。
5. 核对新服务器主机指纹；新服务器指纹变化是预期现象，但必须通过可信渠道确认。
6. 在新服务器部署项目基础设施，恢复数据，再做健康检查和应用连接检查。
7. 本地开发和后端配置验证无误后，再决定是否释放旧服务器。

如果只是换公网 IP、服务器数据仍未迁移，只改 `$ServerHost` 即可；如果是新机器，必须同时
处理数据恢复、密钥、主机指纹和防火墙，不能只改一个地址。

## 7. 常见故障判断

| 现象 | 常见原因 | 处理方向 |
| --- | --- | --- |
| `Connection timed out` | 地址不可达、内网地址、云安全组或防火墙未放行 22 | 先检查 `$ServerHost` 和 `Test-NetConnection` |
| `Connection refused` | 地址可达，但 SSH 服务未监听或端口配置错误 | 检查服务器 SSH 服务和端口 |
| `Permission denied` | 用户名、密码或私钥不匹配 | 检查 `$ServerUser`、`-i` 和服务器授权公钥 |
| 指纹变化警告 | 服务器重装、换机器或地址指向了另一台主机 | 先人工核对，不要盲目删除安全记录 |
| `bind: Address already in use` | 本地 13306 等端口已被占用 | 关闭旧隧道或改用其他本地端口 |
| 隧道窗口“卡住” | `ssh -N` 正在正常保持转发 | 保持窗口打开，另开窗口验证本地端口 |

## 8. 成功标准

- `Test-NetConnection $ServerHost -Port 22` 成功。
- 普通 SSH 登录成功，且没有绕过主机指纹校验。
- 隧道窗口保持运行，没有端口转发错误。
- 本地四个转发端口测试成功。
- MySQL、Redis、MinIO 分别能完成应用层连接。
- 更换服务器时，数据备份、恢复和新主机指纹都经过确认。

## 9. 学习记录

- `10.1.8.2` 是服务器内网地址，不一定能被个人电脑访问。
- `$ServerHost` 当前指向公网 SSH 地址；公网 IP 可能随着服务器更换而变化。
- SSH 主机指纹用于验证服务器身份；SSH 登录密码、SSH 私钥和项目数据库密码是三类不同凭据。
- `127.0.0.1` 的含义取决于命令运行位置；SSH `-L` 的目标 `127.0.0.1` 指服务器本机。
- 隧道解决的是安全连通问题，不解决数据备份和服务器迁移问题。
