# 首期规格：个人学习闭环

状态：已定稿（2026-08-05）
依据：决策票据 #2、#3、#4、#5、#6、#14，调研文档 docs/research/，ADR docs/adr/

## 1. 范围与目标

首期交付个人学习者的完整业务闭环：注册登录、浏览课程、免费报名获得学习资格、学习课程内容、记录进度、完成练习、满足完成条件后生成课程完成证书。字典以课程分类为真实场景随首期实现，掌握字典机制与使用边界。

明确不做（后置能力见 AGENTS.md「阶段门槛与触发检查」和 docs/roadmap.md）：考试、商品订单与支付、组织学习、AI 能力、微服务拆分、内容生产管理（课程内容使用种子数据）、站内信、操作日志、报表导出、定时任务、日志平台。

## 2. 架构形态

- 模块化单体：IAM、Content、Learning 三个业务模块，Assessment 并入 Learning 的 practice 子模块，Gateway 后置。
- 单一 MySQL 实例，iam / content / learning 三个 schema，单数据源，表名全限定，禁止跨 schema join。
- 模块间读走同步接口（事务外），跨模块写走进程内事件（提交后触发，首期最小化落地）。
- 跨模块禁止直接查表，数据访问一律走模块接口。
- 前端 React + TypeScript + Vite 直接访问单体应用，认证走 OAuth2 授权码 + PKCE。

## 3. 模块与数据所有权

跨模块只存逻辑引用（user_id、course_id），展示字段需要时存快照。表清单与字段要点：

### iam

| 表 | 字段要点 | 说明 |
| --- | --- | --- |
| user | id、username、password（BCrypt）、phone、email、display_name、status、created_at、updated_at、version | IAM 独占 |
| role | id、code（LEARNER/TEACHER/ADMIN）、name | 种子数据三行 |
| user_role | user_id、role_id | 多角色 |
| oauth2_registered_client | SAS 标准结构 | 存 SPA 客户端 |
| oauth2_authorization | SAS 标准结构 | 授权状态，JDBC 存储 |
| oauth2_authorization_consent | SAS 标准结构 | consent 记录 |
| dict_type | id、code、name | 字典类型，公共基础数据 |
| dict_item | id、type_code、code、label、sort、enabled | 字典项 |

### content

| 表 | 字段要点 | 说明 |
| --- | --- | --- |
| course | id、title、description、cover_url（MinIO）、category_code（字典）、status、created_by（老师 user_id）、created_at、updated_at | 完成条件在 Content 定义，见 completion_rule |
| completion_rule | id、course_id（唯一）、progress_percent、practice_pass_rate、created_at、updated_at | 课程完成条件，领域词「课程完成条件」，快照进 Learning |
| lesson | id、course_id、title、type（TEXT/VIDEO）、content、sort | 学习内容 |
| practice_question | id、course_id、type、stem、options（JSON）、answer、explanation | 练习题定义归 Content |

### learning

| 表 | 字段要点 | 说明 |
| --- | --- | --- |
| learning_eligibility | id、user_id、course_id、completion_rule_snapshot（JSON 快照）、status、granted_at、completed_at | 唯一约束 (user_id, course_id) |
| learning_record | id、eligibility_id、lesson_id、progress、updated_at | 唯一约束 (eligibility_id, lesson_id) |
| practice_attempt | id、user_id、eligibility_id、question_id、answer、is_correct、attempted_at | 作答记录归 Learning |
| course_completion | id、eligibility_id、user_id、course_id、certificate_no、issued_at | 完成结果与课程完成证书 |

## 4. 认证与授权

- Spring Authorization Server + OAuth2/OIDC + JWT + JWKS，集成进 IAM。
- 注册流程：手机号验证码（mock）+ 用户名密码。SmsSender 接口 + MockSmsSender 实现（日志打印验证码，开发环境可固定值），验证码存 Redis 5 分钟 TTL，同号 60 秒发送间隔防刷。
- 登录：SAS 标准 token 端点（授权码 + PKCE）。
- 登出：jti 写入 Redis 黑名单，登出立即失效。
- 权限：轻量 RBAC（user、role、user_role），权限点在代码内 hasRole 控制。注册默认授予 LEARNER。

## 5. API 契约

- `ApiResponse<T>` {code, message, data}，成功 code=0。
- 业务错误码 4 位分段：1xxx 通用、2xxx IAM、3xxx Content、4xxx Learning。
- HTTP 状态码语义化：200 / 400 / 401 / 403 / 404 / 500。
- 全局异常：@RestControllerAdvice，BusinessException 带错误码，参数校验错误带字段名，兜底处理器记完整日志、响应安全 message。

## 6. 接口清单

### IAM（2xxx）

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| /api/v1/sms/code | POST | 发送注册验证码，body {phone} |
| /api/v1/auth/register | POST | 注册，body {phone, code, username, password}，默认 LEARNER |
| /api/v1/auth/logout | POST | 登出，jti 进黑名单 |
| /api/v1/users/me | GET | 当前用户信息 |
| /api/v1/dicts/{typeCode} | GET | 按类型查字典项（课程分类），公共查询 |
| /oauth2/token、/oauth2/authorize、/oauth2/jwks | | SAS 标准端点 |

### Content（3xxx）

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| /api/v1/courses | GET | 课程列表分页，Redis 缓存示例 |
| /api/v1/courses/{id} | GET | 课程详情（含完成条件） |
| /api/v1/courses/{id}/cover | POST | 封面上传（TEACHER/ADMIN），MinIO 存储 |
| /api/v1/courses/{id}/lessons | GET | 学习内容列表 |
| /api/v1/lessons/{id} | GET | 学习内容详情 |
| /api/v1/courses/{id}/completion-condition | GET | 完成条件（读 completion_rule，Learning 同步读，事务外） |

### Learning（4xxx）

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| /api/v1/eligibilities | POST | 免费课程报名，校验课程存在（走 Content 接口），幂等（唯一约束） |
| /api/v1/eligibilities | GET | 我的学习资格列表 |
| /api/v1/eligibilities/{id} | GET | 资格详情（含快照完成条件） |
| /api/v1/learning-records | POST | 记录学习进度 |
| /api/v1/learning-records | GET | 分页筛选（课程、时间、状态），原生 MyBatis 对比切片 |
| /api/v1/practice-attempts | POST | 提交练习作答，实时判分 |
| /api/v1/course-completions | GET | 我的完成结果与证书 |

完成判定规则：资格授予时快照 Content 的 completion_rule；学习进度与练习结果满足快照条件时生成 course_completion 与 certificate_no，同一资格只生成一次。

## 7. 状态机与删除策略

- course.status：DRAFT / PUBLISHED / ARCHIVED。
- user.status：ACTIVE / DISABLED。
- learning_eligibility.status：ACTIVE / COMPLETED。
- 事实类数据（资格、记录、作答、完成结果）永不删；不提供物理删除接口。

## 8. 关键持久化落地

- MyBatis-Plus 基线：简单 CRUD 用 BaseMapper + LambdaWrapper，复杂 SQL 走 XML，分页插件必须注册，主键数据库自增 BIGINT。
- 原生对比切片：learning_record 分页筛选查询用纯原生 XML 实现（动态 SQL、resultMap、手拼 LIMIT），配 lesson 讲执行模型，仅此一处。
- Flyway 单实例平铺：`db/migration/` 一个目录，版本号全局递增，DDL 全限定表名；Compose init 脚本建三库，JDBC URL 指 iam，history 表落 iam。
- Redis 三用途：登出黑名单、mock 验证码、课程列表缓存示例一个。
- MinIO 收敛版：FileStorage 接口抽象 + MinIO 实现，种子图片托管，Testcontainers 集成测试。

## 9. 测试基线

- 后端：JUnit 5 + Mockito + AssertJ + Testcontainers（MySQL、Redis、MinIO 容器）。
- 前端：Vitest + React Testing Library。
- TDD 优先的规则：资格授予与幂等、完成判定、练习判分、登出失效、验证码防刷。

## 10. 种子数据

- 角色：LEARNER、TEACHER、ADMIN。
- 用户：learner1、teacher1、admin1。
- 课程分类字典：如「前端开发、后端开发、人工智能」，3 门课程各挂一个分类。
- 课程：3 门 PUBLISHED，各含若干 lesson 与练习。
- 课程封面图：Compose 启动脚本灌入 MinIO。
