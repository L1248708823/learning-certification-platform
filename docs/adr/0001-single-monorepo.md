# 使用单仓库承载可独立部署的微服务

项目采用单个 Monorepo 管理前端应用、微服务、基础设施和项目文档；各服务保持独立构建、独立启动和独立部署能力。这样可以让跨服务接口变更、端到端测试、Docker Compose、本地协作和 AI 上下文保持一致，同时避免个人项目过早承担多仓库版本同步与跨仓库 Review 成本。只有当团队边界、发布节奏或权限隔离形成真实需求时，才重新评估拆分仓库。

## Status

accepted

## Considered Options

- 每个微服务独立仓库：部署隔离更强，但当前阶段会显著增加跨仓库协作和契约同步成本。
- 应用仓库与基础设施仓库分离：适合更成熟的部署协作，目前会增加本地开发和变更追踪成本。
