# 按业务边界和维护压力拆分领域上下文

项目初期保持单一根目录 `CONTEXT.md`，不因微服务数量或文件长度自动拆分。只有当候选领域拥有独立词汇与不变量、独立流程与生命周期、明确跨领域关系，并出现词义冲突、独立协作、独立发布或文档定位困难等实际维护压力时，才新增 `CONTEXT-MAP.md` 并拆分上下文；在实现 `organization-service` 前必须复审一次，之后在引入 AI、社区或独立团队协作前再次复审。

## Status

accepted

## Consequences

- 服务边界和领域上下文不强制一一对应。
- 上下文拆分需要迁移词汇、补充领域关系，并更新相关 ADR。
- 早期保持文档简单，后续通过明确门槛控制复杂度。
