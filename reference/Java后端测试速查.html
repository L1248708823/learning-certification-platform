Java 后端测试速查

先看被测范围和依赖边界，再给测试命名。文件放在 test 目录，只说明它是测试源码，不说明测试类型。

四个常用层次

术语被测范围典型工具当前项目
纯单元测试一个类或一个规则，依赖隔离JUnit 5、Mockito、AssertJ暂无
上下文测试Spring Bean 能否组装和启动@SpringBootTest有
Web 层集成测试路由、参数校验、异常、响应契约MockMvc、@SpringBootTest有
基础设施集成测试真实数据库、缓存或对象存储的协作Testcontainers后续
端到端测试真实服务和用户流程Playwright 等后续

判断问题

  1. 只测试一个 Java 类，依赖可以直接传入或模拟吗？是纯单元测试。
  2. 需要 Spring 扫描、依赖注入或配置吗？是 Spring 测试，范围再看是上下文、Web 切片还是完整应用。
  3. 需要真实 MySQL、Redis 或 MinIO 吗？是基础设施集成测试。
  4. 需要先启动应用，通过真实端口模拟用户操作吗？通常是端到端测试或外部服务测试。

从零开发顺序

  1. 写行为例子：输入、前提、期望结果。
  2. 为核心业务规则写纯单元测试。
  3. 实现规则，让测试经历失败、通过和整理。
  4. 需要 Spring 装配时补上下文测试。
  5. 需要 HTTP 契约时补 Web 层测试。
  6. 需要验证 SQL 或真实外部依赖时补 Testcontainers 集成测试。
  7. 最后用少量端到端测试验证关键用户旅程。

是否要先启动项目

测试命令或方式是否手动启动应用原因
Maven 执行 JUnit 测试通常不需要测试进程会创建自己的类和 Spring 上下文
MockMvc不需要请求在测试进程内经过 MVC，不经过真实端口
Testcontainers不需要手动启动依赖测试代码负责启动容器，前提是容器运行环境可用
Playwright 端到端测试通常需要浏览器要访问已经运行的前端和后端
