LESSON 0006

Java 后端测试分层与开发顺序

学会三件事：按依赖边界区分测试，按风险安排测试顺序，知道测试运行时应用是否需要提前启动。

先记住一个原则

src/test 是测试代码的目录约定，不是测试类型。测试类型由它测了多少代码、启动了哪些依赖、是否经过真实端口决定。

每个带 @Test 的方法通常叫一个测试用例。一个测试类可以包含多个测试用例。Maven 负责发现、编译和运行这些测试。

从小到大看测试范围

纯单元测试

测试一个类或一个业务规则。依赖由测试直接传入，外部依赖可以用 Mockito 模拟。它适合验证“给定输入，规则返回什么”，运行快，失败位置清楚。

Spring 上下文测试

使用 @SpringBootTest 启动 Spring 容器，验证 Bean、配置和自动装配能否成立。当前项目的 contextLoads 就属于这一类，也叫上下文冒烟测试。

Web 层集成测试

使用 MockMvc 验证 Controller、参数校验、异常处理、状态码和 JSON 契约。当前的 GlobalExceptionHandlerTest 属于这一类。它不需要打开真实端口。

基础设施集成测试

连接真实 MySQL、Redis 或 MinIO，验证 SQL、事务、序列化和依赖协作。项目计划使用 Testcontainers。测试通常自动起容器，不要求你手动启动 Spring Boot 应用。

端到端测试

通过真实浏览器和真实端口验证完整用户旅程，例如注册、登录、报名和学习。它覆盖范围最大，运行和排查成本也最高，所以数量通常较少。

从零开发怎么写

  1. 先写场景：前提是什么，输入是什么，期望结果是什么。
  2. 先为核心规则写纯单元测试。例如免费课程重复报名时，第二次请求应返回同一份学习资格。
  3. 运行测试，先看到失败，再写最少实现让它通过，最后整理代码。这就是 TDD 的红、绿、重构循环。
  4. 业务类需要 Spring 注入后，再写上下文或更窄的 Spring 测试。
  5. 接口需要稳定响应格式后，再写 Web 层测试。
  6. SQL、事务和真实中间件出现后，再写 Testcontainers 集成测试。
  7. 首期闭环完成后，用少量端到端测试覆盖最重要的用户旅程。

实际项目不必为每个方法都写所有层次的测试。规则风险高就加强单元测试，SQL 风险高就加强数据库集成测试，接口契约变化频繁就加强 Web 测试。

点击测试前要不要启动应用

运行 Maven 测试时，通常不需要先执行 spring-boot:run。测试会在自己的 JVM 进程中创建对象，带有 @SpringBootTest 时还会在测试进程内创建 Spring 上下文。当前两个测试还排除了数据源和 Flyway。

需要真实端口的端到端测试才通常要求先启动前后端。需要 Testcontainers 时，测试会启动容器，但本项目的本机环境约定是依赖容器运行在云服务器上，实际执行前要按项目配置准备容器环境。

当前项目的运行命令

进入 backend 目录后运行：

./mvnw test

Windows 使用：

mvnw.cmd test

只运行一个测试类：

mvnw.cmd -Dtest=GlobalExceptionHandlerTest test

测试报告默认在 backend/target/surefire-reports。绿色只表示这次测试覆盖的行为通过，不等于整个产品首期验收通过。
