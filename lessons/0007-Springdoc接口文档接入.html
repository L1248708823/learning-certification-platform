LESSON 0007

Springdoc 接口文档接入

学会追踪一条接口如何从 Controller 代码，变成可打开、可试调的 Swagger UI 页面。

这次到底接入了什么

当前项目接入的是 Springdoc OpenAPI。它在 Spring Boot 运行时读取 Controller、请求 DTO、响应 DTO 和参数校验注解，生成标准 OpenAPI 文档。Swagger UI 读取这份文档后显示页面，并提供 Try it out 调试入口。

Controller + DTO + Bean Validation
              ↓ Springdoc 在运行时扫描
        /v3/api-docs JSON
              ↓ Swagger UI 读取
 /swagger-ui/index.html 页面

这里有两个边界。Springdoc 负责生成接口契约，Swagger UI 负责显示和调试。它们都不处理注册、验证码或数据库业务。

第一步：Maven 加 Starter

我在 backend/pom.xml 加入了下面的依赖：

<dependency>
  <groupId>org.springdoc</groupId>
  <artifactId>springdoc-openapi-starter-webmvc-ui</artifactId>
  <version>2.9.0</version>
</dependency>

starter-webmvc-ui 的名字包含三个信息：它适用于 Spring MVC，能生成 OpenAPI，也带 Swagger UI 的静态资源。Maven 会下载它和它声明的间接依赖。IDEA 的 Maven Reload 与命令行 mvnw.cmd test 都会完成这一步。

当前项目使用 Spring Boot 3.5，因此选 Springdoc v2。Springdoc v3 对应 Spring Boot 4，版本线不能混用。

第二步：理解自动生成的范围

现有代码Springdoc 自动得到的文档信息
@PostMapping("/code")HTTP 方法 POST 与路径 /api/v1/sms/code
SmsCodeRequest请求体字段 phone 及其类型
@NotBlank、@Pattern必填约束和正则规则
ApiResponse<Void>成功响应外层的 code、message、data 结构

自动生成不理解业务规则。例如验证码五分钟有效、六十秒内不可重复发送、错误码 2001 的含义，都无法从 Java 类型推出。因此需要少量补充注解。

第三步：放全局信息到配置类

OpenApiConfiguration.java 创建了一个 OpenAPI 类型的 Spring Bean：

@Bean
public OpenAPI learningPlatformOpenApi() {
    return new OpenAPI().info(new Info()
            .title("在线教育与职业认证平台 API")
            .version("v1"));
}

@Configuration 让 Spring 扫描这个类，@Bean 把返回对象放进 Spring 容器。Springdoc 发现这个 OpenAPI 对象后，把 title、version 和 description 合并进自动生成的接口定义。方法名可以按项目语义命名，Springdoc 关心的是返回类型和 Bean。

第四步：每种注解解决一个问题

注解当前代码的位置负责的信息
@TagSmsController、RegistrationController、DictController页面中的业务分组
@Operation每个公开接口方法接口摘要和业务限制
@ApiResponses每个公开接口方法成功和真实失败状态码
@Schema公开请求、响应字段和 ApiResponse调用方需要知道的字段语义、样例、只写属性
@HiddenContractDemoController从业务接口目录排除测试演示入口

例如发送验证码接口的注解说明了有效期、发送间隔和 409 响应。这个信息属于外部接口契约，放在 @Operation 和 @ApiResponses 合适。

@Operation(summary = "发送注册验证码",
        description = "验证码有效期为五分钟；同一手机号六十秒内只能发送一次。")
@ApiResponses({
        @ApiResponse(responseCode = "200", description = "验证码已发送"),
        @ApiResponse(responseCode = "409", description = "发送间隔未结束，错误码为 2001")
})

JavaDoc 仍然保留。它面向读代码的人，解释设计原因、事务边界和后置计划。@Schema 面向接口调用方。两者只在外部契约需要时写相同信息，避免维护两份无意义的说明。

第五步：为什么还要测试文档

文档端点也是应用的一部分。依赖升级、路径冲突或错误配置都可能让页面失效。我在 GlobalExceptionHandlerTest 增加了两项 Web 层测试：

GET /v3/api-docs              → 200，且有项目 title
GET /swagger-ui/index.html    → 200

它们通过 MockMvc 在测试 JVM 内调用 Spring MVC，不需要先启动真实端口，也不需要连接数据库。测试配置关闭 IAM，因此这一层验证文档能力和隐藏规则；注册、验证码、字典接口的完整联动由 IamRegistrationAndDictionaryIT 在 mvn verify 阶段结合 MySQL、Redis 验证。

现在怎样亲自检查

  1. 在 IDEA 的 Maven 工具窗口执行 Reload，或在 backend 目录运行 mvnw.cmd test。
  2. 用你已配置 DB_PASSWORD、REDIS_PASSWORD 和 SSH 隧道的启动配置运行 LearningPlatformApplication。
  3. 打开 http://localhost:8080/swagger-ui/index.html。
  4. 展开 IAM / 注册，先看 POST /api/v1/sms/code 的 Request body、Responses 和 Schema。
  5. 点击 Try it out 后再执行。验证码不会出现在 HTTP 响应中，本地 MockSmsSender 会记录它。

生产环境不应默认公开文档端点。后续接入认证和部署配置时，要根据访问策略关闭或限制 /v3/api-docs 与 /swagger-ui/**。
