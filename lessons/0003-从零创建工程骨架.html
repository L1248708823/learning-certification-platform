LESSON 0003

从零创建工程骨架

还原首期-01 创建项目的完整动作链，分清哪些是工具按部就班生成的，哪些是需要自己一行行手写的。

本课目标

完成本课后，你应该能说出这个后端工程每一个文件的来历，也能自己从零搭一个同款骨架：知道哪些命令可以交给工具，哪些内容必须自己决定。

两条创建路径

候选方案两个。一个是 Spring Initializr（start.spring.io 网页或 IDEA 新建项目向导），选好版本和依赖，它把 pom、主类、配置文件、测试类一次性生成好；另一个是完全手写，一个文件一个文件地建。

主流做法是 Initializr 起步再手写补充，快而且不容易漏。本项目实际走的是完全手写，原因是本次在命令行环境里操作，而且每个文件都带教学注释，手写本身就成了学习材料。两条路径到达的终点相同，差别在过程。你以后自己搭项目，用 Initializr 更快，但希望你能看懂生成出来的每一行。

按部就班生成的部分

  1. 版本事实：Spring Boot 用哪个版本、Flyway 和 MySQL 驱动被托管到什么版本，这些从 Maven Central 的 maven-metadata.xml 和官方文档查出来，是查证步骤，工具和人都要按这个来。
  2. Maven Wrapper：一条命令 mvn wrapper:wrapper 生成 mvnw、mvnw.cmd 和 .mvn/wrapper/maven-wrapper.properties，内容是工具决定的，不用人写。
  3. 依赖下载：mvn validate 时 Maven 按 pom 声明去中央仓库拉 parent 和依赖，也是自动化。

如果走 Initializr 路径，主类、application.properties、测试类也会由生成器产出，这部分就属于生成而非手写。

自己手写的部分

工具能生成骨架，但生成不了决策。这些文件全部手写：

  1. pom.xml：选哪些 starter、要不要 flyway-mysql、注释怎么写，是技术决策。
  2. application.yml：数据源指向 iam、Flyway 开关、Actuator 只暴露 health 和 info，是配置决策。
  3. V1__baseline.sql：基线语义写在迁移脚本注释里。
  4. logback-spring.xml：输出格式、滚动策略。
  5. compose.yaml 和 deploy/：工具没有这个，三库拆分、健康检查、钉镜像版本全是自己定。
  6. .gitattributes：行尾策略，工程规范。
  7. 测试类：排除数据源自动配置的写法来自对 Boot 自动配置机制的理解。
  8. 文档：ADR 0007、本课、调研 Amendment，都是人写的。

判断标准一句话：这个文件的内容是事实还是决策？版本号、托管依赖是事实，查来就行；依赖选型、配置含义、边界约定是决策，必须自己定。

完整动作序列

  1. 查版本事实（Maven Central、官方文档），确定 Boot 3.5.16、Java 21。
  2. 建目录：backend/、deploy/mysql/init/，写 .gitignore 和 .gitattributes。
  3. 手写 pom.xml，mvn validate 验证能解析。
  4. 手写主类、application.yml、logback-spring.xml、V1__baseline.sql、测试类。
  5. mvn wrapper:wrapper 生成 Maven Wrapper。
  6. 手写 compose.yaml 与建库脚本，用 Python 校验 YAML 语法。
  7. 写 ADR 与教学文档，code-review 两轴审查，修复发现的问题。
  8. 提交，在票据上留验证清单等人工验证。

其中第 1、3、5 步在常规流程里会被 Spring Initializr 合并成一步，其余步骤无论哪条路径都一样。
