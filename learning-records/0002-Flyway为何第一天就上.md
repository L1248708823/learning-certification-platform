# 为什么数据库迁移工具第一天就要上

用户问"一开始就考虑 Flyway，是因为明确知道要迁移才这样做吗，正常开发是不是不会"。这是一个关于工具引入时机的真实疑问，答案是：正常开发恰恰会第一天就上，原因如下。

## Evidence

- 代码有 git 管版本，数据库结构（表、字段、索引）没有版本控制就会出现多环境结构漂移。
- Flyway 迁移脚本随代码进仓库，一次版本控制管代码和结构两样东西，是数据库的 git。
- 工具先于业务落位：骨架阶段 V1 是空基线，第一张业务表（首期-03 IAM 建表）出生时就在版本控制里，无需事后 baseline。
- 国内主流做法，调研文档选择理由：主流、简单、与 Boot 集成好。

## Implications

- 后续教学涉及数据库结构时，改动一律走迁移脚本，演示"加字段"这类真实迁移场景。
- 遇到"工具是否提前引入"的问题，用"机制先于内容落位"的原则判断：先问是否确定会有内容，再决定时机。
- 用户对"为什么第一天就上工具"类决策敏感，解释时先讲痛点（多环境漂移）再讲时机。
