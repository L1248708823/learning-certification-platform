# Java 测试分层与执行边界

用户开始系统学习 Java 后端测试，当前重点是区分测试类型、理解测试文件的编写思路，以及知道运行测试时是否需要先启动应用。

## Evidence

- 契约层：`GlobalExceptionHandlerTest` 用 `@SpringBootTest` + MockMvc，排除数据源，离线可跑。
- 冒烟：`LearningPlatformApplicationTests` 只验证上下文能启动，`app.iam.enabled=false`，不连库、不连 Redis。
- 规则单元测试：`VerificationCodeServiceTest`、`RegistrationServiceTest` 用内存存储和假 Mapper，不启动 Spring，不需要 Docker。
- 真实依赖集成测试：`IamRegistrationAndDictionaryIT` 用 Testcontainers 起 MySQL 和 Redis，文件名以 `IT` 结尾，只在 `mvn verify` 跑。本机没装 Docker 时不要跑这一层。

## Implications

- `src/test` 是 Maven 的测试源码目录，里面不是同一种测试。
- 分类看被测范围：纯规则、Spring 装配、HTTP 契约、真实基础设施。
- 从零写业务规则时，先写能红的单元测试，再补集成测试锁住 Redis 和唯一约束这种跨资源行为。
- `mvn test` 通常不必先手动启动应用。`mvn verify` 需要本机 Docker。
- 测试强度跟风险匹配：验证码防刷、一次一码、写库失败码还在，这些必须有测试。
