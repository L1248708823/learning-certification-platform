# Java 测试分层与执行边界

用户开始系统学习 Java 后端测试，当前重点是区分测试类型、理解测试文件的编写思路，以及知道运行测试时是否需要先启动应用。

## Evidence

- 当前 `backend/src/test` 有 `LearningPlatformApplicationTests` 和 `GlobalExceptionHandlerTest`。
- `LearningPlatformApplicationTests` 使用 `@SpringBootTest`，只验证 Spring 应用上下文能否启动，并排除数据源和 Flyway。
- `GlobalExceptionHandlerTest` 使用 `@SpringBootTest`、`@AutoConfigureMockMvc` 和 `MockMvc`，验证 Web 路由、参数校验、全局异常处理、HTTP 状态码和 JSON 响应。
- 当前项目还没有只创建业务类和模拟依赖的纯单元测试，也没有连接真实 MySQL、Redis、MinIO 的集成测试。
- 用户已有前端工具函数测试经验，希望通过真实业务切片理解后端测试分层和 TDD。

## Implications

- `src/test` 是 Maven 的测试源码目录，不代表其中所有文件都是同一种测试。
- 测试分类要看被测范围和依赖边界：是否启动 Spring 容器、是否连接真实基础设施、是否通过真实网络和用户流程。
- 从零开发一个业务规则时，默认先确定行为，再为核心规则写纯单元测试；需要验证 Spring 装配时写上下文测试；需要验证 HTTP 契约时写 Web 层测试；需要验证 SQL 和外部基础设施时再写真实依赖集成测试。
- 运行当前测试通常不需要先手动启动 Spring Boot 应用，因为 Maven 测试会在测试进程内创建需要的 Spring 上下文；只有端到端测试或连接一个已经运行的外部服务时，才需要先启动目标服务。
- 后续 IAM、Content、Learning 业务实现需要逐步补充单元测试和 Testcontainers 集成测试，测试强度应与业务规则和外部依赖的风险匹配。
